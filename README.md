# Novel to EPUB Converter

## 🚀 Назначение

Утилита для скачивания веб-новелл с сайта freewebnovel.com и преобразования их в формат EPUB с сохранением:

- Готовые файлы по умолчанию пишутся в каталог **`books/`** в корне проекта (код и артефакты сборки не смешиваются с книгами; каталог в git не отслеживается)
- Метаданных (автор, жанры, статус)
- Обложки
- Полного текста глав
- Навигации по главам

## 🧩 Использование

### Установка зависимостей

```bash
pip install -r requirements.txt
```

Пакет `requests` устанавливается с extra **`[socks]`** (через `requirements.txt`): так подтягивается **PySocks**, необходимый для прокси **SOCKS** (`socks4`, `socks5`, `socks5h` и т.д.). Для работы только через **HTTP(S)-прокси** достаточно стандартных зависимостей `requests`.

### Базовое использование

```bash
python novel_epub.py --novel shadow-slave
```

### Расширенные параметры

```bash
python novel_epub.py \
  --novel shadow-slave \
  --start 5 \
  --max 100 \
  --output "My Novel.epub" \
  --delay 2.0
```

С опциональным прокси (все HTTP(S)-запросы идут через него):

```bash
python novel_epub.py --novel shadow-slave --proxy http://127.0.0.1:8080
# краткая форма:
python novel_epub.py -n shadow-slave -p socks5h://127.0.0.1:1080
```

| Параметр   | Короткий флаг | Описание                                                                     | По умолчанию   |
| ---------- | ------------- | ---------------------------------------------------------------------------- | -------------- |
| `--novel`  | `-n`          | Название новеллы в URL                                                       | `shadow-slave` |
| `--start`  | `-s`          | Стартовая глава                                                              | `1`            |
| `--max`    | `-m`          | Макс. глав (`0` = все до конца или до ошибки)                                | `0`            |
| `--output` | `-o`          | Имя EPUB; без пути — файл в **`books/`** (по умолчанию `books/<novel>.epub`) | см. `-h`       |
| `--delay`  | `-d`          | Задержка между запросами (сек)                                               | `0.5`          |
| `--proxy`  | `-p`          | URL прокси для всех запросов (см. ниже)                                      | не задан       |

### Прокси

Параметр **`--proxy` / `-p`** задаёт один URL, который используется и для `http://`, и для `https://` целевого сайта.

Поддерживаемые схемы (как в `urllib3` / `requests`):

| Схема                     | Назначение                                  |
| ------------------------- | ------------------------------------------- |
| `http://`                 | HTTP-прокси                                 |
| `https://`                | HTTPS-прокси (CONNECT)                      |
| `socks4://`, `socks4a://` | SOCKS4 / SOCKS4a                            |
| `socks5://`               | SOCKS5 (разрешение имён на клиенте)         |
| `socks5h://`              | SOCKS5 с разрешением имён на стороне прокси |

Если в строке **нет схемы** (например `127.0.0.1:8080`), подставляется **`http://`**.

Примеры:

```text
http://127.0.0.1:8080
http://user:password@proxy.example.com:3128
socks5://127.0.0.1:1080
socks5h://127.0.0.1:1080
```

При старте в лог выводится только тип прокси (например `Using proxy (socks5)`), без полного URL — чтобы не попадали учётные данные в логи.

### Пример вывода

```text
Starting download: shadow-slave
Using proxy (http)
Downloaded 5 chapters...
Downloaded 10 chapters...
Successful saved: /path/to/project/books/shadow-slave.epub
Chapters uploaded: 150 | Time: 312.45с
```

Точные строки зависят от объёма загрузки и от того, указан ли прокси.

## ⚠️ Критические правила

1. **Задержка между запросами**: не устанавливайте значение ниже `0.5` сек, чтобы снизить риск блокировки.
2. **Стабильность соединения**: скрипт повторяет запросы при сетевых сбоях с увеличивающейся задержкой.
3. **Доступ к сайту**: при ошибках `403` может потребоваться обновить заголовки или использовать прокси.

## 🔄 Механизм сохранения прогресса

Промежуточный результат сохраняется рядом с целевым файлом: например `books/novel.epub.tmp`. После успешного завершения временный файл переименовывается в целевой EPUB.

Программа сохраняет прогресс:

- каждые 5 загруженных глав;
- по сигналу прерывания (Ctrl+C);
- в блоке `finally` перед финализацией EPUB.

## 🛠 Технические особенности

- Выходные EPUB по умолчанию в каталоге **`books/`** (можно задать свой путь через `-o path/to/file.epub`)
- Опциональный **HTTP / HTTPS / SOCKS**-прокси для всех запросов
- Поддержка относительных URL изображений в тексте глав
- Очистка контента от рекламных вставок
- Проверка MIME-типа обложки
- Логирование этапов загрузки
- Повтор запросов при ошибках сети и сервера
